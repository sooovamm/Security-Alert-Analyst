# AI-Powered Security Alert Analyst

A retrieval-augmented (RAG) assistant that triages SOC security alerts. Given a
raw alert it returns a structured, evidence-grounded assessment — classification,
risk score, reasoning, recommended action, confidence — for a **human analyst to
review**. The LLM is strictly advisory and never executes security actions.

> **Build status: Foundation + dataset complete.** Runnable backend (health
> endpoints), frontend skeleton, Docker/Compose, config, a **45-alert validated
> dataset** with a Pydantic schema, a SQLAlchemy model, and an idempotent seed
> script are in place. RAG pipeline, LLM analysis, and the `/analyze-alert`
> endpoint are built in later sprints.

## Dataset (Sprint: dataset)

- **45 alerts** in `data/alerts/alerts.json`, verdict-balanced **15 benign / 15
  suspicious / 15 malicious**, spanning all 7 required categories. Generated by
  `data/alerts/build_alerts.py` (validated at build time) so the dataset is
  reproducible, not hand-edited.
- Every alert has all 10 fields: `alert_id`, `timestamp`, `hostname`, `username`,
  `source_ip`, `process`, `command_line`, `severity`, `category`, `description`.
  Telemetry only — **no verdict is stored in the dataset**; expected labels live
  separately in `eval_labels.json` for evaluation.
- **Validation:** `app/schemas/alert.py` (Pydantic) rejects malformed alerts —
  bad severity/category, invalid IP or timestamp, missing/blank fields, or
  unknown extra fields.
- **Persistence:** `app/models/alert.py` (SQLAlchemy). Import with:
  ```bash
  cd backend && source .venv/bin/activate
  python -m app.seed      # validates then upserts into SQLite (idempotent)
  ```

## Run locally (no Docker)

Backend:
```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload         # http://localhost:8000
curl http://localhost:8000/health     # {"status":"ok",...}
```

Frontend (separate terminal):
```bash
cd frontend
npm install
npm run dev                            # http://localhost:5173 (proxies /api -> :8000)
```

The app boots and `/health` works **without** an API key. `/health/ready`
reports whether the OpenAI key and data files are present.

## Run with Docker Compose

```bash
cp .env.example .env      # required: compose reads .env (add your OpenAI key later)
docker compose up --build
# frontend: http://localhost:8080   backend: http://localhost:8000/health
```

The frontend container serves the built SPA via nginx and reverse-proxies
`/api/` to the backend, so the browser makes same-origin calls.

## Testing & checks (backend)

## Security posture (foundation)

- **No secrets in source.** All config via env vars / `.env` (gitignored); only
  `.env.example` is committed. App boots without the API key.
- **Input separation (enforced in later sprints).** The system treats alert
  data as untrusted, retrieved knowledge as context, and instructions as
  system-owned; alert text is never allowed to act as instructions.
- **Advisory only.** LLM output never triggers a security action.
